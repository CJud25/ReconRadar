# ADR-016: Remove Opportunity Recon and the legacy synthetic feasibility engine

## Status

Accepted for Phase-3 identity hardening

## Date

2026-07-20

## Context

The product ("App A — Opportunity Evidence Packet") has one identity: a cited
evidence packet, never a manufactured score. The trunk still carried a
synthetic "Opportunity Recon" capture board whose
`ready_to_pursue_score = feasibility × confidence × urgency` was exactly the
manufactured feasibility score the product's positioning says it is unlike —
one nav click away from the non-numeric evidence scanner. The BD page's
legacy synthetic calculator UI was already deleted in an earlier merge; its
engine (`feasibility.py`) and several doc promises about it survived as dead
weight. The owner-approved reconciliation plan (2026-07-18, decision D1,
default CUT) directs removal of the capture board and its engine.

## Decision

Delete the manufactured-score surface and everything that existed only to
feed it:

- `pages.render_opportunity_recon`, its `_cached_opportunity_recon` helper,
  and the "Opportunity Recon" entry in `PAGE_RENDERERS` and
  `roles.ALL_PAGES`.
- The "Upcoming-contract readiness" metric and "Leading synthetic capture"
  insight box on `render_home` that read from the capture board.
- `metrics.opportunity_readiness` (the `ready_to_pursue_score` formula).
- `src/tens_hq/feasibility.py` in full, including `FEASIBILITY_VERSION =
  "FEASIBILITY-1.0"`, `evaluate_geography`, and `feasibility_markdown`. Its
  only remaining `src/` consumer was the now-deleted Opportunity Recon page.

Display vocabulary that promised the deleted engine (README, architecture
doc, governance surfaces in `pages.py`, the product blueprint, and prior
ADRs) is corrected in this same phase so the docs and the app cannot drift
apart. ADRs are append-only: prior decisions are annotated with an "Update
2026-07-20 (ADR-016)" note rather than edited or deleted.

## Alternatives considered

- **Keep the capture board but strip only the visible score:** rejected — the
  underlying `ready_to_pursue_score`/`feasibility_score` values would still
  flow through the board's table, chart hover data, and prefill payload, so
  the manufactured-score surface would survive under a thinner label.
- **Keep `feasibility.py` for a possible future re-use:** rejected — it has
  no remaining consumer after the capture board is removed, and an unused
  scoring engine sitting in `src/` is exactly the kind of dead weight this
  phase exists to cut.

## Consequences

- Navigation is ten pages (was eleven); `roles.ROLE_PAGES` visibility is
  unaffected because Opportunity Recon is gone from `ALL_PAGES` for every
  role.
- FORECAST-1.1's scope narrows to the site/portfolio forecast, trajectory
  fan, and source-score contracts (ADR-010); the capture-ordering consumer no
  longer exists. (Since the Phase-3 vocabulary commit the tag is stamped
  `SYN-FORECAST-1.1` — see the ADR-010 update note.)
- The synthetic `opportunities` DataFrame generated by `synthetic.py` is
  **deliberately retained** as inert generated data: it is facts, not scores,
  `validate_demo_data.py`'s dataset counts depend on it, and it is a
  candidate seed for a future A2 Radar-handoff slice. Nothing in the app
  renders it today.
- Any future BD capture-prioritization feature must be built as cited
  evidence (following the Eligibility Gate / Contract Facts / Capture Window
  / Geography / R2b pattern on the Opportunity Packet), never as a
  re-introduced numeric score.
