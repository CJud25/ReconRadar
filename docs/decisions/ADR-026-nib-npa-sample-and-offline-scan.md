# ADR-026: Bundle a synthetic NIB/NPA sample and an offline scan affordance

## Status

Accepted for the product-legibility one-shot

## Date

2026-07-23

## Context

The tracker's nonnumeric readiness lifecycle (Scan -> evidence review ->
route resolution -> Validated) is a documented centerpiece of the product,
but `data/samples/` shipped only a **Services** workbook
(`sample_pl_services.xlsx`) and a Radar handoff JSON. The `NIB_NPA` source
kind requires its own exact header set — `Nonprofit Agency Name`, `City`,
`State`, `Zip Code` (`connectors/abilityone.py:50-55`) — which the Services
workbook does not carry. Uploading the Services sample under the NIB source
fails closed with `HEADER_NOT_FOUND` (by design — the parser's exact-schema
check must not fuzzy-match). A stranger with no network access could
therefore drive the Services lane offline but never the NIB/NPA lane, so the
tracker's readiness-toward-green path could never be demonstrated end to end
without a real workbook (§5.4 / §15-#6).

One upload cannot satisfy both evidence gates (route resolution needs both a
directory row and a service-catalog row from two distinct source kinds), so
the fix is a second bundled sample, not a change to the existing one.

## Decision

1. **A new committed fixture, not a `tests/fixtures/` reuse.**
   `scripts/make_sample_nib_npa.py` (mirroring the structure of
   `make_sample_pl_services.py`) generates
   `data/samples/sample_nib_npa.xlsx` — the exact `NIB_NPA` headers, a
   SYNTHETIC-marker title row ("SYNTHETIC EXAMPLE - not a real
   NIB/SourceAmerica directory (illustrative demo data only)"), and three
   invented agency rows in Denver/Aurora, CO — the same worksite city the
   bundled radar handoff and PL Services sample already use, so all three
   samples line up for a single offline walkthrough. The generated bytes are
   committed directly (the OOXML zip is not byte-stable across regenerations,
   matching the existing PL Services sample's own documented caveat).
2. **An in-form offline affordance, not a parallel scan path.**
   `_render_scan` (`bd_page.py`) gains a checkbox, "Use the bundled SYNTHETIC
   NIB/NPA example instead of an upload", placed inside the existing
   `st.form("public_scan_form")` next to the file uploader. On submit, if
   checked, the handler forces `source = SourceKind.NIB_NPA.value`, reads
   `_sample_nib_npa_bytes()` (mirroring `_sample_pl_services_bytes`), and
   uses a fixed sample filename — bypassing the "choose a workbook" warning
   but never bypassing the public-source attestation checkbox, and never
   touching the parse/persist path (`WorkbookScanner.run_scan` is called
   exactly as it is for a real upload).
3. **No label collision with the existing sample affordance.** The Origin
   handoff intake and the Opportunity Packet's PL cross-reference already use
   the exact label "Use the bundled SYNTHETIC example instead of an upload"
   (pinned twice, verbatim, by `test_demo_tour.py`). The new label inserts
   "NIB/NPA" between "SYNTHETIC" and "example", so it is never a superstring
   of the pinned text and the pinned occurrence count stays at 2.

## Alternatives considered

- **Reuse the Services sample under the NIB source kind:** rejected — the
  connector's exact-schema check would fail closed (`HEADER_NOT_FOUND`),
  which is the correct behavior for a strict offline parser; changing the
  parser to fuzzy-match would weaken the same discipline every other source
  kind relies on.
- **Route the sample through a separate, un-attested code path:** rejected —
  the offline sample must exercise the same `WorkbookScanner.run_scan` a real
  upload does (provenance row, dedup, idempotency), and the operator still
  ticks the same public-source attestation checkbox; the only thing the
  checkbox changes is where the bytes come from.
- **Widen the sample's row set to also satisfy the Services schema in one
  file:** rejected — the two source kinds have disjoint header sets by
  design (one names the performing nonprofit agency and location; the other
  names the CNA and service type), and a single workbook that tried to
  satisfy both would misrepresent what either an NIB/NPA or a Services
  export actually looks like.

## Consequences

- A stranger can now run a green NIB/NPA scan fully offline from the bundled
  sample, immediately after creating a case, with no upload required.
- `data/samples/` grows to three artifacts (PL Services, Radar handoff,
  NIB/NPA); `scripts/validate_demo_data.py` is unaffected — none of these are
  part of `DemoData`.
- Automated coverage: a primary unit test parses the actual committed
  `sample_nib_npa.xlsx` bytes through the real `NIB_NPA` schema and asserts
  three `PARSED` rows with the expected agency/city/state values (the real
  proof the bundled file satisfies the schema offline); a secondary `AppTest`
  seeds a case directly against the isolated test ledger and confirms the new
  checkbox renders, wired, with no exception.
